# 阶段文档 2 · 施工（每个阶段从开工到跑通）

> 完成判据：部件图上所有部件完工、整体跑通、承重部件全部过轻验收（用户明确跳过的记欠条，不阻塞进通关，欠条随大考回头题补）。**整阶段首次联跑之前先 Read `3-通关.md`**——大考第 0 题的押注邀请（「心里押一下会跑成啥样」，不等回答）必须在跑之前发出，跑完就补不了了。跑通后走通关仪式。

## 理念：本阶段在学什么

施工是**机制 + 边界维度的主场**：每个承重部件的因果链讲通（机制），每堵墙亲手撞过（边界）。学习点不是平铺清单，是**挂在部件图上的**——点挂在结构上才串得起来、才记得住（v1 子格清单的病根就是点散了）。

## 策略

> **本阶段的动作归属与回复粒度以 `SKILL.md` 的统一节奏入口为真源。** Quick 下 AI 连续完成服务于同一判断问题的低风险、可逆机械动作；只有新产品取舍、明显风险、不可替代的用户体验或推翻方向的证据才停。下文“用户亲手跑”等旧表述在 Quick 下只适用于亲手操作本身就是学习证据的实验。

1. **部件图当结构骨架**：学习点 = 承重部件携带的认知；学习顺序沿图上的边走（数据从哪流到哪，就从哪学到哪），学完自动串成结构，不用事后缝合。
2. **施工期零设问（2026-07-30 v2.5，用户同日三次点名后定稿）**：施工期你不向用户抛任何问题——找坑式预判（v2.3 已禁）和现象预测（v2.3 曾保留）全废。用户要的节奏是「讲解 → 实践 → 测验时再考」。坑的学法只有一条：跑 → 撞上 → 你当场把因果讲透（现象在先、讲解紧跟，不问「你说说为什么」）。检验集中在通关大考；他自己冒出的问题和主动给的解释，是最高价值的岔路，认真接。
3. **产品即教具优先**：实验默认做在产品身上（零迁移损耗、动机连续）；离开产品单造教具要过判据（见实验设计）。
4. **放大镜不切片**：放慢用放大镜，不改地图形状。

## 流程

### 一、部件图开工仪式（🔒 焊死 · 单独成轮）

阶段开工第一件事是立**部件图**，讲完就停，不夹带第一个部件的内容。图两层：

- **数据流一层**（开工就亮）：一张 Mermaid 图，谁连谁、数据往哪走，≤7 节点。图上标两样：**上一阶段已有 vs 本阶段新增**（承接自动可见）、**承重 vs 填充**。
- **决策一层**（开工**只列问题不给答案**）：本阶段要拍的委托人决策写成问题挂着（「引擎怎么调用，到子进程部件时你拍」）；建到那个部件、用户拍板后再回填答案与理由。开工就亮答案 = AI 替用户拍完决策再通报，正是铁律三要防的。

开场白 3 句打住：承接（图上哪些节点是上一阶段已有的；S1 没有上一阶段，这句改说「从零起步、全图皆新」）、本阶段新增什么、第一个承重部件是谁。**图只讲结构，不讲施工顺序**——对着图说「我们先做 A 再做 B」就成了报菜单，删。讲完问「图有疑问吗」，等用户应了才进第一个部件。

部件图真源放该阶段学习记录文件顶部施工态区（落盘规矩见 `4-笔记.md`）。
> 翻案注记（2026-07-28）：v1 的「整级逻辑总览 + 子格定位开场」（2026-07-09/07-13 两条焊死规则）由部件图接替——它防的翻车（「知道每小块干嘛，连起来没概念」）现在靠一张常驻的图防：可视、可指、可考。

### 二、部件分两类，待遇不同

- **承重部件**（带新能力块 / 新形状 / 有墙要撞）→ 讲机制因果链，实验按准入做，过三问后落要点。
- **填充部件**（样板、配置、固定写法）→ AI 直接做，一句话带过，不讲、不考。

分拣尺子：**这一处改了，用户对「它为什么这么跑」的理解会不会变？** 会变 = 承重；不会变 = 填充。

### 三、按边施工（结构单位 = 图上的边；互动单位 = 一个判断问题）

- 图上的边仍是一环因果，但不强制一条边占一轮。Quick 下，同一个判断问题涉及的相邻边和机械动作可以合并讲解与执行；跨到新判断、风险或方向变化时才停。每次仍要指图定位。**施工期不设问（v2.5，沿革：v2.2 限 1 道 → v2.3 收窄现象预测 → v2.5 全废）**：用户的问题随时插进来、最高优先。
- **换部件时首句指图一句**：「A 完了，现在长 B，B 的输出喂 C」——位置、缺口、咬合一句带全。
- 一个承重部件讲不完就按边分几轮，**不拆进阶梯、不编号**。

围绕当前承重部件，顺序固定：
1. **它为什么存在 / 起什么作用**——先给存在的理由，让用户脑子里有画面。
2. **怎么实现的（先逻辑，不碰代码）**——大白话讲清靠什么、底层逻辑、为什么这么做。
3. **代码怎么诠释这套逻辑（后代码）**——代码对着逻辑讲。只讲服务于这件事的代码；属于后面阶段的机制一句话点名「那阶段再讲」，不展开。
4. **实验按准入来**（见下）——动手 → 跑 → 看现象，主语全是用户；现象回来你讲透。

**搭台要提前探好环境**：要用户跑的命令先后台探一遍（依赖在不在、端口占没占），保证他一跑就通。环境摩擦最毁心流。

### 四、交棒节奏（关键步停 · 实验准入 = 两分 + 事后分流）

1. **你**：搭好台，把这一环直接讲清（v2.5：不抛问题；沿革见策略 2。全新概念直接教这条照旧——2026-07-03 用户点名：逼他瞎蒙很挫败）。
2. 用户提问或主动说「我猜会…」→ 最高价值，立刻接：提问走岔路（第八节），他的猜法记住、跑完拿现象对照给他看。
   > 翻案注记（2028-07-28 三分法废除 → v2.2 预测题分拣 → v2.5 预测题整个废除，只剩用户自发的猜）。
3. 到写代码的点：若仍有会改变产品边界或造成明显损失的委托人决策，让用户拍板；已有决定或可安全推断的偏好直接复用。AI 写完后一句话讲清代码替哪个判断干活，并按统一节奏入口决定由谁运行——不设“先预判再跑”的闸。
4. **执行与观察按节奏分流**：Quick 下由 AI 运行自动验证并展示可判断的证据；只有亲手操作会产生不可替代体验时才由用户运行并描述现象。非 Quick 节奏可保留更多用户实操。
5. **你**：拿现象把因果讲透；撞了墙（含故意埋的）就现象在先、讲解紧跟——不问「你说说为什么」（v2.5）。他主动给过猜法/解释的，对着现象校给他看。

### 五、实验设计：首选「撞墙 / 对照式失败」

**最狠的实验是让它当场失败给用户看**，尤其是制造两种情况的对照——认知是撞出来的，不是听来的。

- **故意撞墙**：设计一个会失败的动作，让用户亲眼撞上限制，永远记住这堵墙在哪。
- **对照式失败**：同一个动作在两种条件下以不同方式失败/成功，差异本身就是那块认知。
- 其次才是「改一行 / 删一处看会怎样」。无论哪种，写到**能照着做的粒度**。

> 范例（真实跑过，效果极好）：讲「为什么网页存盘非要后端」——做一个保存按钮，两种方式下点：一种报「请求发不出去（没人接）」，一种报「有人接但这活我不会（501）」。一眼分清「没人接 ≠ 不会这活」。

**独立教具（可选 · 2026-07-29 用户拍板）**：实验默认做在产品身上。离开产品、单独造一个最小教具，**仅当满足三判据之一**：
1. **动不起**：在产品上做要改的东西太多，或会弄坏产品状态。
2. **看不清**：知识点被产品语境糊住，一次要碰好几个部件才看得见它。
3. **造不出**：对照式失败需要一个产品里造不出来的「坏版本」（上面 501 范例就是这类）。

**教具三规格**：①小——几分钟跑完，不变成第二个项目；②一次性——用完即弃、不维护、不进阶梯不占笔记；③**必须回指产品**——跑完立刻一句「你刚撞的这堵墙，就是产品里 X 部件那堵」（治迁移损耗，不能省）。教具也必须让用户亲手跑、亲眼看现象、自己验尸，不是看演示。

### 六、要点落盘触发（原「轻验收」，v2.5 去提问化）

一个承重部件走完、**用户亲眼看过它在真机上跑的现象** → 该部件的要点段即时落盘学习记录施工态区（落盘规矩见 `4-笔记.md`）。不再顺口设问——深度标尺三问全部移到通关大考。
- 用户施工中自然说出的复述、判断、原话 → 记进要点段当成文化素材（施工期不采就没了）。
- 他卡住、提问、或现象对不上 → 上放大镜，通了再回主线。
- 疑虚的点不当场考，记进学习地图「认知模型待加固」，大考回头题带。

### 七、放大镜（部件内放慢的唯一合法动作)

执行 `SKILL.md` 的「局部放大协议」，本节只规定施工形态：

- **客观触发**：用户无法定位当前路径；现象/测试推翻假设；新规则与当前决策冲突；AI 说不出具体验收证据。普通复杂、文件多、用户问了一个可直接回答的小事实，都不自动触发。
- **先钉返回锚点**：原节奏｜当前判断问题｜原定下一动作｜触发证据。写进学习地图的临时栏，防止讲清局部后忘了原来要做什么。
- **最小断点原则**：只放大那条断掉的图上边、错误假设或冲突规则。需要图时补最小背景图；需要实验时只制造能区分两种解释的最小对照。用户主动预测后，公开 AI 原假设、依据和不确定性，再拿证据比较。
- **收敛三证据**：①冲突已改写成可执行规则；②证据能解释异常或结果；③没有仍影响当前判断的未决阻断。三项齐全 → 清掉临时锚点，一句话「刚修清 X；回到 Y，继续 Z」，恢复原节奏与下一动作。任一不满足就继续最小验证；若断点已扩成产品边界或全项目理解问题，升级节奏或建议独立“项目梳理”，不伪装成局部放大。
- **实验版**：当用户反馈「太顺了 / 没踩实 / 不知道怎么通关的」，对着图掐断与当前判断有关的一条边（注释一行、断开一个连接），直接运行最小对照并展示现象；只有亲手操作产生不可替代体验时才交给用户。
- **零永久留痕判据（防退化回子格）**：返回主线时，学习地图和部件图不得因为一次临时放大增加永久节点、边或阶段；临时返回锚点必须清除。若证据说明地图本身错了，就不是“放大结束后一字不差”，而是显式走岔路收口②或③，留下有依据的正式修改。放大镜内可以做实验，但不配验收仪式、不编号、不进阶梯。
> 翻案注记（2026-07-28）：旧「当场细分 M2→M2.1/M2.2」废除——拆出来的子格不满足「能跑」判据，还把结构切碎。用户喊「没踩实」的信号照旧最高优先，只是响应从切片机换成放大镜。

### 八、岔路：随时双向展开（这个 skill 的灵魂）

- **岔路双向发起**：不只你判断「他卡了」才岔；**用户自己冒出的「为什么 / 是不是这样」就是最高价值的岔路口**——立刻跟上去。
- **有前置缺口先补地基**：疑问暴露出更底层的认知缺口时，先补，再回来。
- **用「做」来回答，但有度**：看得见/能撞的概念 → 动手 demo 答（教具判据适用）；小事实缺口 → 一句话确认就走，别硬凑实验毁节奏。不管哪种，话要讲清——不是「只做不说」，是「能用做来说就别干说」。
- **收口三结局，走哪条由用户拍板**（铁律三），收口时点一句名：
  - **① 回归主线**（默认）：一句话拎回——「这条搞定，我们在 S3 的 X 部件，继续」。习得挂当前施工阶段的要点段、条目前标「岔路：」（见 `4-笔记.md`）。
  - **② 转正为主线**：越挖越大、用户拍板「先把它做完」→ 立成新阶段（或加进当前部件图）插进阶梯、原阶段标注断点，并顺检：下游阶段是否受波及（受→同轮改）、产品侧是否新增或翻案（是→同轮落 PLAN.md）。整个动作走 🔒「改了规划就当场落真源」（见 `4-笔记.md`）。
  - **③ 沉淀为待办**：值得做但当下不展开 → 地图记一笔（待加固虚点或阶梯末尾备选），回主线。
