# 阶段文档 4 · 笔记（所有落盘规范，被 1/2/3 引用）

> 本文档管「落在哪、怎么写」。任何落盘动作（建笔记 / 刷地图 / 要点落盘 / 成文化 / 能力库 / 存档）前必须已读。完成判据：本次触发的落盘全部落完；下一步：回到触发它的那份阶段文档继续。
> 落盘的**时机**由各阶段文档定（要点落盘触发见 `2-施工.md` 第六节，通关落盘四件见 `3-通关.md` 硬关卡）；本文档只定「落在哪、怎么写」。

## 理念：本阶段在学什么

笔记管**记忆外部化 + 复利资产**。用户记忆一般，认知必须落在外部才留得住：学习记录管「读 = 复习」，学习地图管「AI 无缝接管」，能力库管「跨项目复利」。**你建、你落盘，用户不动笔。**

## 策略

1. **真源唯一**（定义与判据见 SKILL 写作原则；本文档负责落地分工——谁装什么、指针放哪）。
2. **读者分工**：每份文件为一种读者优化——交接单信息密、复盘文流畅可读、能力卡一句话粒度。
3. **随做随落、变一次落一次**：活文档不等「以后」。
4. **深度跟认知增量走**：Quick 只记录本次修改、最小背景、关键边界和验收证据；不为了笔记完整而系统重述整个已有项目。机械过程不进入学习记录。

## 二、🔒 改了规划就当场落真源（焊死，别拖到"以后"）

阶梯和部件图会被真实学习进展逼着变形——要尊重变化，但变化只在对话里说了不算：**阶梯形状变了 → 立刻落学习地图；部件图变了 → 立刻落该阶段学习记录顶部施工态区；剧本/架构/决策新增或翻案了 → 立刻落 PLAN.md；能力块边界被推翻 → 立刻改卡**。判据：刚才这轮对话里，哪个真源对应的东西形状变了？变了 → 现在就落，再继续讲下一块。
翻案条目带一句「旧方案 + 为什么翻」——真源是现状、不是历史账本，但翻案理由留在被改的那处；改完顺手搜一遍旧值，确认没有副本残留。
（为什么焊死：事做了、没落真源 → 真源滞后 → 下次续学按过时地图走偏。"以后顺手补"必被认知节奏挤掉。变一次落一次。）

## 三、学习地图（AI 续学交接单）

四区排序：接管协议最顶、动态状态紧随、背景沉底。模板：

```markdown
# 学习地图 · {要做的东西}
> 这份给 AI 续学用；人想看习得去同文件夹 `学习记录/`（每阶段一份文件）。

## ⚡ AI 接管协议（新对话第一件事，按序做）
1. 先读「现在在哪」→ 接在那一步，别重做已完成的（代码已改好的别重写）。产品工程项目：顺带读代码目录 `PLAN.md`，产品与工程现状以它为准。
2. 守统一节奏入口：默认 Quick / 用户掌判断、AI 扛执行 / 一轮解决一个判断问题；只有高信息判断点才停。
3. 搭台前先抛一道图问（细则见 skill 的 references/3-通关.md「续学图问」——含答不出怎么办）。
4. 看「认知模型待加固」，续学路上补、通关时大考带回头题。
5. 按「怎么重启环境」搭好台；低风险机械动作继续执行，只有不可替代体验或有后果的决策才交给用户。
> 指针而已，细则以 SKILL.md 及其 references/ 为准。

## 📍 现在在哪（每次都更新 · 续学的事实底座）
- 进度：S? ✅ / 🔄 / ⬜
- 当前阶段部件图：真源在 `学习记录/S?.md` 顶部施工态区，这里只记一行——施工到哪个部件、哪条边
- ⏸ 手正悬在哪一步（最重要）：代码已改了啥、正等用户做啥、接着做还是重做
- 代码现状快照：每个关键文件现在已有哪些活
- 下一步动作：具体到那条命令 / 那一行
- 怎么重启环境：cd … && 起服务 → 开哪个地址；谁改了要重启、谁热更新

## 🗺️ 要去哪（阶段性变 · 全局方向）
- 阶段阶梯表（一层；行格式与分辨率递减规则见 references/1-立项.md「画阶梯」）
- 认知模型待加固：三问不过关的虚点 + 对应接下来哪个阶段（API 函数名叫不对不算虚点，不进这里）
- 手边比喻世界：破冰素材库（只在新概念首次出场用一句、紧跟真名；SKILL 写作原则「比喻只破冰」硬边界适用）

## 🎯 这是什么（几乎不变 · 背景兜底）
- 目标 + 啥样算成 ｜ 剧本要点/参考 ｜ 代码在 {路径}、习得在 `学习记录/`、（工程项目）PLAN.md ｜ 能力块在 `../_能力库.md`
- 用户画像 / 偏好（理解力、爱追问啥、表达偏好）
```

**「现在在哪」是命门，随时同步、不只在节点更新**：断档最常发生在「代码刚改完、实验还没跑」的半空中状态。**每改一处代码、每把控制权交给用户前，顺手刷新「⏸ 手悬在哪 + 代码现状快照」**。自检：一个只能读这份地图的空白 AI，照协议走会不会接错？会就补到不会。

**存档口令（2026-07-10 用户点名）**：用户说「存档 / 刷新 / 刷图 / 先到这 / 我要走了」→ 立刻把「现在在哪」全量刷到当前一秒：⏸ 手悬在哪（含讲到哪个部件哪条边、放大镜进行到哪、卡点破没破）、代码现状快照、下一步动作。**覆盖旧值，不追加。** 冗余判据：空白 AI 读完能从正确一步接上——够这标准就停笔，过程、历史、感想不进地图。落完只回一句「已存档，回来从 X 接」。

## 四、学习记录（记录写法五条 + 结构 + 两拍）

文件命名：`S1 · 标题.md`（如 `S1 · 菜单栏住进一个图标.md`），按编号自然排列，打开一个文件 = 复习那一阶段。读者是**已走过一遍的人**。

**记录写法五条（硬要求）：**

1. **逻辑重组、用自己的话重讲**——别按时间顺序抄（被动重读效果差），要重构（生成效应，重构比实录记得牢）。
2. **框架用可迁移概念名 + 结构节点名搭**（此要求仅限复盘笔记，讲解期不受此限）——骨架是概念名、结构节点名 + 它们之间的逻辑（子进程、管道、`canvas.json`、server）。API 函数名可以出现，但不是骨架、不作要求（词汇判据见 SKILL 委托人坐标系）。每带入一个结构节点就说清它在逻辑里的位置。**这条可以多写**——因果链讲透值得花笔墨（砍的是噪音，不是铺平逻辑的字）。比喻的退场规则**全局适用**（见 SKILL 写作原则）：笔记里至多破冰一句、紧跟真名。
3. **坑分两类、分流**——**坑本身 = 关键认知**（「写文件≠画布刷新」「AI 报成功≠真成功」）→ 化进正文叙事当转折引擎（"按直觉该…—没有，因为…"）；用户原话自然缝进正文（"你当时一句『…』点破了它"）。**纯操作小坑** → 移出正文，收进小节末尾平铺的 `#### ⚠️ 这一段踩过的小坑`（不折叠，想看看、不想看滑过）。判据：**不涉及主框架/主逻辑/关键的，移；会干扰理解主框架的，更要移。**
4. **逼主动回忆，钩子只放衔接处**——正文顺、好读、不埋钩子；「抛问 → 答案折叠」放在段与段、部件与部件的接缝（检索练习）。
5. **砍废话与冗余**（最易翻车，铺开时必查）——删报幕词（"先钉一个框架""最自然的疑问是"）；删水词（"最扎心""狠狠撞到"）；同一个"为什么"只论证一次；前面阶段讲透的一句指回不复述。判据：**删掉它，这阶段的知识或因果链少了吗？没少 = 删。** ⚠️ 但因果转折要留（"但…没有，因为…"）——它是记忆钩子，不是废话。

**结构模板**（成文化后的终态）：

```markdown
# S? · {阶段标题}
> {项目名} · 这份给人看（复盘文，读=复习）；续学接管看上级文件夹的 `学习地图.md`。

{通关终版：mermaid 部件图——结构与流向，谁连谁、数据往哪走}

{开场：三五句极简框架，说清这阶段在干嘛}

**本阶段拍过的决策**：{决策 → 选了什么 → 为什么（一行一条）}

> {第一个钩子：抛问}
> <details><summary>参考答案</summary>{答案}</details>

### {小标题一：框架长出的第一根枝}
{流畅成文，概念名+结构节点名搭框架，认知坑化进叙事}
> {段间钩子：抛问}
> <details><summary>参考答案</summary>{答案}</details>

#### ⚠️ 这一段踩过的小坑
- {纯操作小坑，平铺}

{流畅成文}

- Q：…
  <details><summary>参考答案</summary>{要点}</details>
```

**可视化**：
- 写进笔记的图**一律 Mermaid，不许 ASCII 顶替**（执行漂移高发点：有的认真画、有的顺手敲 ASCII 自我合理化"也清晰"）。ASCII 只许用于终端对话即兴梳理。
- **部件图就是总图**：开工立施工态版（放文件顶部施工态区），通关成文化时**刷成终版**放开场——施工中长了新节点，终版以真实走过的为准。
  > 翻案注记（2026-07-28）：旧规「总图整级通关才画、早画=坑」废除——那是怕子格没齐强写缝合；v2 的图开工就要（学习本体），「会变形」靠通关刷版解决。
- 方向灵活（LR/TB、subgraph 按可读性挑）；图管结构与流向、文字管定性与钩子，图上不堆大段字。
- 批量重写时自检：每阶段开头有部件图终版吗？有没有偷用 ASCII？

**两拍、两个时机**：
- **施工态（随做随落，触发见 `2-施工.md` 第六节）**：文件顶部 = 部件图施工态版 + 决策清单（问题态/已回填混排）；正文区 = 已过轻验收的承重部件**要点段**——主张 / 为什么 / 坑 + 一句承接上个部件 + **用户自己的原话**（自然复述的或验收里说的，成文化时要缝进正文，施工期不采就没了）；坑先全堆着不分流。顶部挂 `🚧 本阶段未通关，成文/钩子/自测通关时补`。不写开场框架、钩子、自测（部件没齐，强写=瞎编）。
- **岔路收口的习得同样即时追加**：挂当前施工阶段的要点段、条目前标「岔路：」；属于后面阶段的先照挂、成文化时归位。
- **通关成文化（一次）**：要点段重写成流畅复盘文——部件图刷终版、补框架+首钩子、各部件要点焊成连贯正文、**此刻才把坑分流**、接缝塞钩子、文末补自测、顺全稿、删 🚧 和施工注释。
- 成文化/迭代旧记录时，**先对照读一遍学习地图**——地图里的岔路、画像、上下文复盘文里未必有，两份一起看才不偏。

## 七、旧项目迁移（v1/v2 遗留的处理）

续做旧项目、读到旧编号体系（M1~M6、M4.1/M4.2 子格串）时，**迁移是接管的第一步**：先重切落图、再按新图接上。规则：

1. **以「整个 M 级」为单位判断**：级内全部完成 → 历史原样保留（M 编号不改、旧记录不重写、状态 ✅ 照旧）；级内有未完子格 → **整级重切**（已完成的子格变成新阶段部件图里已完工的部件，不单独成级）。
2. **重切产物用 S 编号，从旧序列最大数字 +1 起续**（例：旧阶梯到 M6 → 新阶段从 S7 编起），避免与历史 M 编号撞车。切法按 `1-立项.md` 阶段四判据：能独立跑的立成阶段，不能跑的并回当部件。
3. **状态**：重切出的新阶段一律标 🔄 或 ⬜，**不许直接标 ✅**——旧子格跑通 ≠ 过大考；通关走 `3-通关.md` 正常仪式，别造旁路。
4. **重切方案给用户过目拍板**（铁律三：阶梯形状是委托人决策），拍完当场落地图。
5. **顺手升级旧地图的「⚡ AI 接管协议」区**为本文档第三节模板的协议文字（旧协议含已废除的 v1 规则，不升级则每次续做都撞一次新旧冲突）；其余区保留原状。
