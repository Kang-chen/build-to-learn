# 阶段文档 1 · 立项（从想法到第一架阶梯）

> 完成判据：硬门五样经用户集中确认 + 落盘完成（见流程第 7、8 步）。下一步：Read `2-施工.md`，进 S1 开工。
> 本文档也管**一切要动阶梯形状的动作**：通关滚动刷新要改阶梯、岔路转正立新阶段、图问失败拆阶段、旧项目重切——动之前按「阶段四判据」和「分辨率递减」办。

## 理念：本阶段在学什么

立项是**可行性维度的主场**。四维认知里，机制和边界在施工学、验收在通关练；而「我的愿望对应世界上存在的什么能力」——主要就发生在立项。所以立项的学习目标不是往讨论里塞知识，而是：**产品讨论的过程本身，就是一次「愿望 → 能力块」翻译的示范和练习**。这个翻译动作是委托人最可迁移的能力——练多了，用户下个产品自己就会拆。

## 策略（四条，从理念推出）

1. **翻译可见**：把用户的剧本场景翻成能力块时，翻译过程摊开给他看，不黑箱。
2. **预测参与**：能力块上桌后让用户猜「哪块最难、哪块有坑」（凭生活直觉可猜：权限、联网这些他有感觉）；猜想标到阶梯对应阶段上，到时撞墙有对照。
3. **能力库对照**：扫库结果亮给用户（「这五块里两块你攒过卡」），让他体感「库越厚、下个产品越敢想」的复利。
4. **决策留白**：立项只拍方向性形状；施工期的决策留给部件图，不透支后面的学习机会。

## 流程（八步：先聊透、再确认、最后落盘）

> **节奏先看 `SKILL.md` 的统一入口。** Quick 下八步仍是思考检查表，不等于八轮对话：先复用项目记录和用户历史，把安全可推断项合并成一份确认载体；只为会改变产品边界或造成明显损失的缺口停下来。正式硬门仍集中确认一次，不靠零散点头。

### 1. 探底
听用户讲第一遍想法，**不打断**。同时后台扫 `{笔记根目录}/_能力库.md`。（环境探测放第 5 步之后——形状没定，不知道该探什么。）

### 2. 剧本拷问
把产品聊成**剧本**：几条「当…（你做了什么）→ 然后…（你希望看见什么）」的场景。用户讲故事，你转写成场景清单。

- **一次一问，走完决策树每一枝**；每问自带推荐答案或 2-3 个具体候选（不甩抽象词）。
- 问的全是产品侧：给谁用、什么时刻用、边界情况（「划的是一整段呢？」「没网呢？」）、什么样算成了。**技术词汇零出现。**
- 有趣的来源 = 场景本身（用户讲自己的使用故事），不靠段子。
- 用户答不上来的枝：给推荐答案让他点头或改，不悬空。

### 3. 翻译桌（学习维度的核心动作）
把剧本摊成**能力块清单**——每块**人话命名**（「让程序在任何窗口都听得见你按键」，不写技术名），逐块标记：

| 标记 | 含义 |
|---|---|
| ✅ | 能力库里有卡（点名哪张，亮给用户） |
| ✔ | 世上有现成技术，AI 确认可行 |
| ⚠️ | 有墙（授权、环境、平台限制），到对应阶段会用真实证据验证 |
| ❓ | AI 也不确定，需要验证——老实说 |

然后**立项预测题**：「这几块里你猜哪块最麻烦？为什么？」——听他的直觉，**不全揭晓答案**，留一句「S? 会用实验证据验证」。

用户回答后，立即公开你的初始判断、依据与不确定性，并比较双方各自发现的风险。可以把必须依靠实验裁决的结论留到对应阶段，但不能隐藏评价基准，让开放预测退化成猜老师心里的答案。

### 4. 学习目标问句
「这个东西你想学到什么程度？」三档候选：**只要跑通 / 能讲出原理 / 能迁移着做下一个**。答案决定最终验收重点：**跑通证据 / 机制与边界 / 新场景迁移**。三档都由 AI 执行机械动作、用户掌握有后果的判断与验收。

**学习目标不等于节奏档位**：前者规定最终掌握标准，后者由 `SKILL.md` 统一入口按风险、陌生度和证据临时选择。用户选“能迁移”不代表每轮都要 Deep；低风险既有项目仍可 Quick，只把最后的迁移验收做扎实。分工标记也不能覆盖“用户掌判断、AI 扛机械执行”的总原则。

### 5. 技术形状
可行性你自己兜底（翻译桌已完成）。要用户拍的只有**方向性形状**：2-3 条路线、人话取舍（「界面放原生层完成度上不去，放网页层现成能力多但要搭一座桥」），带你的推荐。**不出选型题**（「用 SwiftUI 还是 AppKit」这种不问）。
形状拍定 → **同轮后台探环境**：这条路线要用的语言/工具在不在、能不能跑——别等开工才发现跑不起来。

### 6. 画阶梯
从终点倒推核心链路，切成几个**阶段**：

- **命名与判据**：各级统一叫「阶段」，编号 S1/S2/S3……**S1 的产物 = MVP**（唯一的一个），之后每阶段加一块。判据不变：**每阶段收尾 = 产品又长了一块且整体能跑** + 通关仪式——「加功能」不许滑成功能清单。
- **阶段四判据**（引用锚名就叫这个）：①自己能跑、看得见；②结构容量合适（部件图一屏装下：节点 ≤7、承重部件 ≤2~3；装不下 → 拆成两个都能跑的阶段，禁止拆成不能跑的半成品）；③接在上一阶段成品上；④至少一个承重部件（没有 = 纯打磨，标 🤖）。
- **判据的适用时点**：完整检查只在阶段**开工**时做（立部件图那一刻才判得了结构容量）；画阶梯时远阶段只需方向对、大致接得上。
- **分辨率递减（2026-07-29 用户拍板）**：下一阶段切实；往后每阶段一行字；更远写「待定，做到再拆」。**远处禁止细化**——远阶段必然被近阶段的真实体验改写，画细 = 伪精度 + 自我锚定。
- **阶梯是当前最佳猜想的路标序列，不是合同；唯一的承诺是下一阶段。改阶梯不是计划失败，是计划在正常工作。** 滚动刷新的触发点 = 每次通关仪式（见 `3-通关.md`）。
- 把用户在翻译桌的预测**标到对应阶段上**（撞墙时回照）。
- 阶梯每级一行：编号 / 名字 / 跑成什么样 / 承重部件路标（远阶段可写「待定」）/ 分工 / 状态。

> 翻案注记（2026-07-28/29）：旧判据「只逼出一个新概念」废除（子格机制的理论根，切碎结构）；「一次坐下来做完」的时间判据没立过——结构容量才可判。

### 7. 硬门（承 brainstorming 的 HARD-GATE · 有确认载体，不靠零散点头）
五样凑齐后，**集中列一条清单、单独一轮**让用户逐项确认：**产品一句话 + 剧本场景清单 + 做成判据 + 学习目标档位 + 第一架阶梯**。过程中的零散点头不算过门；用户改哪样就改完再确认。**五样确认前不动一行代码、不落任何项目文件。**

### 8. 落盘（硬门过了才落，动作前先 Read `4-笔记.md`）
- 真产品工程项目：代码目录建 `PLAN.md`（内容规格见 `4-笔记.md` 真源分工总表；翻案纪律见其第二节）。
- 所有项目：在 `{笔记根目录}` 下建项目文件夹（`学习地图.md` + `学习记录/`）、登记 `_项目索引.md`。
- **告诉用户**：笔记落在哪、代码落在哪。

产品中途要变：不搞变更提案目录，走岔路收口②（见 `2-施工.md`）+ PLAN.md 翻案条目（见 `4-笔记.md` 第二节）。

> 「读懂一份现成代码」型项目照用本流程：剧本换成「读懂它的哪几种行为」，阶梯每阶段 = 读懂一块机制 + 在它身上做一个实验。
