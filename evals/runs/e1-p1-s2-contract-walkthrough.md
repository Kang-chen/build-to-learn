# S2 契约走查：错误模型与不同预测

> 性质：确定性文档走查，不是盲测模型运行。目的仅是证明规则覆盖关键路径；真正的行为回归留给后续 eval 阶段。

## E1 · 错误模型不会拖成全项目课

场景：用户认为“文件扩展名决定它属于哪个项目”，但项目索引和来源关系表明，一个 Markdown 是某个 skill 项目的测试产物。

期望路径：

1. 触发证据是“当前分类假设与项目索引冲突”，不是“知识库文件很多”。
2. 返回锚点保存：Quick｜判断该文件是否属于已有项目｜随后更新分类｜索引证据与扩展名直觉冲突。
3. 只放大“项目身份由来源/用途还是扩展名决定”这一条边，用一个同扩展名、不同项目身份的反例验证。
4. 收敛时形成可执行规则“项目身份优先看来源和用途”；反例解释原异常；当前归类没有其他阻断。
5. 一句话返回：“刚确认身份看来源与用途，不看扩展名；回到 Quick，继续更新分类。”不讲完整知识库架构。

错误路径：因为出现一个分类错误，就扩写全部知识库目录、另立学习阶段，或没有收敛证据便说“讲清了，继续”。

## P1 · 用户预测与 AI 不同时不藏答案

场景：用户预测“现有测试会失败”，AI 原先预测“会通过”，两者都有依据，结论取决于脚本是否覆盖该分支。

期望路径：AI 先公开“我的原假设是会通过，因为契约检查包含该关键词；不确定点是它可能没覆盖行为分支”，再说明用户预测抓住了什么，直接运行测试，以结果更新判断。预测不同本身不升级整个节奏。

错误路径：只说“我们跑跑看”而隐藏原假设；或把 AI 的预测当标准答案纠正用户；或额外增加一轮让用户猜实现细节。

## 走查结论

- E1 覆盖客观触发、返回锚点、最小断点、三证据收敛与恢复 Quick。
- P1 覆盖假设透明、保留不确定性和证据优先。
- 两例都不增加用户考试题量；最终报告再交付改动位置、测试结果和残余不确定性。

## G1 · 真实用户失败：实际案例仍在考隐藏领域知识

RED 观察（2026-08-12）：S2 通关题先用抽象术语提问，用户要求改成真实执行案例。重述为 `output/articles/spatialprop-wechat.md` 分类故障后，又用填空要求用户自行补出“来源/用途优先于路径/扩展名”的分类规则和正反例。用户把流程概念“最小背景”填进分类规则，并明确答不出反例。

失败归因：题目表面具体，但没有组成一个完整的场景证据包；它把本阶段要检验的“局部放大与返回”换成了未充分教学的分类领域回忆。连续换皮追问同时突破了单题预算。

修复契约：真实场景题先给目标对象、已知记录/规则、失败现象和要作的判断，正确判断必须可由这些证据与本阶段已教模型推出。用户答后直接公开 Agent 的参考判断与依据、对照差异；信息包缺失先算教学缺口，不连续换皮重考。

GREEN 结果：`references/3-通关.md` 已增加场景题输入包和答后教学输出；`check_s2_contract.py` 从 RED 失败转为通过。参考判断已直接教给用户，没有再出第四种题面。

用户对 S2 核心机制的最终表达是“保存主线位置 → 聚焦当前断点与证据 → 判断信息是否足够解决并返回 → 继续主线”。按本阶段目标评为 8/10；没有从缺失输入中猜出分类领域规则不再扣分。待加固项是把最终证据包表达得更具体，留给 S3 行为回归观察。
