# S3 行为回归：兼容与发布

## 范围

验证 S1/S2 规则在 Quick、局部 Standard 和 Deep 中是否保持一致：学习目标与节奏分离、AI 扛机械执行、风险证据不可省、局部放大可收敛、场景题证据充分、最终交付证据包。

## RED · 独立 Agent 首轮压力测试

### Q1 · 熟悉项目的小规则更新

失败：Agent 按 active reference 执行时，在部件图后停下来问“图有疑问吗”，通关前又先等用户认可考法。真实正式题虽然只有一道，却多出两个空转确认。

命中的原文：`图有疑问吗，等用户应了才进第一个部件`；`用户认可再开考`。

### Q2 · HTML 导出按钮的隐藏边界

失败：任务应初始 Quick，但“一个必要基础陌生”与“异常出现后局部放大”允许两种矛盾路由；README 与施工文档还保留强制用户亲手运行的旧预期。

### D1 · OAuth、重试与持久状态

失败：双轴设计基本正确，但 reference 仍写“动手 → 跑 → 看现象，主语全是用户”；普通轻验收欠账规则可能被用来跳过安全、幂等和恢复证据；“只要跑通”可能被误判为“不想学”，或仍统一考迁移四问。

### G2 · 用陌生项目考本阶段原理

失败：S3 的用户学习目标是“能讲出本次 skill 修改的原理”，但通关题凭空换成 OAuth、重试和持久状态。即使题面列出了足够事实，用户仍需先建立另一个项目的模型，增加与本阶段无关的理解负担；回答无法区分是 Build-to-Learn 原理没学会，还是陌生题材造成干扰。暴露出旧规则只要求“场景输入完整”，没有要求题目延续用户实际参与过的经验。

## GREEN · 最小修复

- 移除部件图确认轮与考法预确认；图后同轮进入第一个判断，考法与唯一正题同条发送。
- 清除根规则、施工与教程里的旧动作归属；所有节奏都由 AI 运行可重复机械验证，不可替代体验才交给用户。
- 明确学习目标与节奏是两条轴；“只要跑通”仍属于 Build to Learn，通关题按学习目标选。
- Standard 只在开工所需基础无法最小补足，或异常经一次最小检查仍需多轮证据时启用；隐藏边界本身不提前放慢。
- 高风险边界没有实际证据不得欠账、不得通关；可以用安全 mock / sandbox 代替危险真实失败。
- 中英文 README 同步默认 Quick、一个判断问题、局部放大和证据充分的场景题。
- 通关题同时满足证据自足与经验连续：默认使用用户刚参与的真实修改；只有“能迁移”目标且领域前置已建立时才跨情境。越界题作废、不评分并改用当前项目材料。

## Fresh-context 盲测

盲测只提供当前 skill 路径和用户请求，不提供预期答案、已知漏洞或修改说明。

### HTML 导出

PASS：Agent 选择 Quick，自动定位、修改和联跑；只有无法推断导出格式或真实浏览器体验不可替代时才停。最终题给出具体失败现象并考内容级验收，报告包含改动位置、正反验证、浏览器证据和残余不确定性。

### OAuth 集成

PASS：Agent 将学习目标设为“只要跑通”，同时因安全与多个陌生机制选择 Deep；安装、配置、mock 和测试由 AI 完成，仅真实 scope 授权交给用户。用假服务器、假时钟和临时状态库保留失败边界，不在真实 API 上制造危险故障。
